## Геометрия и сборка

Для каждого прозрачного исходника подготовлена SVG-обёртка `*-display.svg`. Она встраивает исходный PNG без изменения его байтов и устанавливает viewBox вокруг детали; прозрачные поля больше не влияют на размеры CSS. Это кодовый контейнер для отображения, не новый растровый рисунок. Внутренний PNG встроен data URI: SVG, подключённый как CSS-image, не зависит от загрузки вложенного внешнего файла.

Границы viewBox указаны как x/y/width/height:

| Деталь | ViewBox | Правило |
| --- | --- | --- |
| chassis-display.svg | 17 / 159 / 1502 / 710 | CSS border-image, slices 100 / 130 / 110 / 130; ширины 22 / 24 / 26 / 24 CSS px. Центр без fill, отдельно CSS-бордовый фон |
| deck-display.svg | 33 / 147 / 2105 / 424 | CSS border-image, slices 130 / 230 / 110 / 230 fill; desktop widths 32 / 52 / 28 / 52. На mobile 18 / 24 / 20 / 24 |
| wheel-display.svg | 46 / 40 / 1162 / 1162 | Квадратный viewport; transform-origin 50% 50%; одинаковый размер по x/y, не сжимать в эллипс |
| keycap-display.svg | 132 / 100 / 989 / 1059 | Сохранять пропорцию; буква поверх верхней площадки; 19 разных DOM-экземпляров, четыре с animation hooks |
| spin-face-display.svg | 52 / 171 / 1918 / 425 | Отдельная абсолютная лицевая часть; текст/иконка накладываются HTML; её локальный translateY не меняет box/focus |

Круглые вырезы, текстуры бумаги, подписи и маски барабанов создаются CSS/HTML; нет текста или выбранных значений, запечённых в PNG. Не растягивать всю машинку единым изображением. Рамка и основание используют растяжимую середину и устойчивые углы; размер окон растёт по DESIGN.md при длинных значениях. Все три результата имеют общую высоту.

Порядок: статичный кабинет → CSS-заливка корпуса и рамка → бумажные окна с HTML-лентами → статичное основание → stationary housing → движущаяся лицевая часть SPIN с её текстом. Колёса прикреплены к бокам корпуса; их rotation не вращает сам корпус. Prompt — самостоятельная непрозрачная бумажная панель. Copy располагается ниже preview и снаружи его scroll.

На ≥768 px доступны колёса и декоративные клавиши; ниже они скрыты. Ниже 640 px барабаны вертикальные, подписи слева, SPIN и Copy занимают внутреннюю ширину. Сцена допускает центральный crop на телефоне: лампа/стакан не обязательны для понимания. На длинной мобильной странице фон заканчивается спокойным #26343E; не вытягивать комнату по высоте текста.

## Сохранение, проверка и пределы

Подробный результат текущих проверок: [VERIFICATION.md](artwork-review/VERIFICATION.md), [JSON](artwork-review/VERIFICATION.json).

- Все шесть растровых masters, пять SVG-контейнеров, manifest, отчёт, исходные генерационные промпты и итоговый художественный эскиз лежат в проекте.
- `node docs/design/assets/inspect-assets.mjs` читает PNG и обновляет отчёт прозрачности/границ/SHA-256. Сам рисунок не меняется.
- `node docs/design/artwork-review/build-review.mjs` воспроизводит SVG-контейнеры и два статических HTML-экрана. Не создаёт raster screenshot и не изменяет PNG.
- HTTP и локальные ссылки проверены отдельно от визуального воспроизведения. Browser подключение снова завершилось EPERM при загрузке browser-client.mjs; внешний браузер не запускался. Browser-геометрия, читаемость реальной CSS-сборки и zoom остаются проверками этапа 3; PNG визуально просмотрены.
- Исходные четыре approved mockups и v09 сохранены. Их Tone — историческая надпись; новые материалы используют Topic / Format / Angle.
- Размер шести PNG masters около 10 MB; SVG обёртки дополнительно встраивают те же байты. Это набор исходников для передачи в реализацию, не утверждённый сетевой бюджет MVP. В production подключать только один формат каждой детали; подготовить оптимизированные экспорты, измерить загрузку и фактический contrast при интеграции. Не грузить gallery и исходники одновременно с интерфейсом.
- На этапе 2 нет новых зависимостей, коммита, push или deployment. Все изменения локальные. Следующий этап — React-интеграция дизайна и движения деталей, затем проверка работающего экрана.
