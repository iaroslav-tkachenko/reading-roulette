## 8. Геометрия барабанов и длинный текст

Desktop: три равные рамки. В каждой одинаковые верхняя подпись 24, верхний сосед 24, центральная область min-height 104, нижний сосед 24, дополнительные внутренние поля 12. Высота не зафиксирована. Центральный результат растёт по содержимому.

Mobile: каждая рамка — двухколоночная строка: слева подпись, справа бумажное окно с верхним соседом, выбранным результатом и нижним соседом. Верхний/нижний декоративные ряды по 18; выбранная область минимум 56, для dense и ширины ≤359 — минимум 88. Внутри выбранного результата вертикальный pad 8. Текст центрируется горизонтально и вертикально; мелкие пиктограммы допустимы только рядом с короткими значениями на desktop, на mobile и в dense убираются.

Порядок работы с текстом:

1. `minmax(0, 1fr)`, достаточная доступная ширина и обычный перенос по словам.
2. Если хотя бы одно выбранное значение длиннее **28 символов**, включается общий модификатор **dense для всех трёх барабанов**: 22 desktop / 18 mobile. Никакого бесконечного shrink-to-fit.
3. Если результат не помещается в обычные 1–3 строки, высота всех трёх рамок растёт до требуемой. Полное значение остаётся видимым.

`line-height: 1.25`, `white-space: normal`, `overflow-wrap: anywhere`, `hyphens: manual`. Переносы в изображениях не являются жёсткими `<br>` в данных. Не применять ellipsis, line-clamp, fade mask или fixed-height с hidden overflow к **выбранному** тексту. Убирать соседей можно декоративной маской внутри их отдельных рядов; они не должны занимать место выбранного значения.

Согласование высоты обычным CSS: `.reels` — grid, `.reel` — растягивающийся дочерний grid с одинаковыми фиксированными рядами для label/neighbors и auto-рядом для результата. На desktop элементы одной строки получают высоту самого высокого. На stacked mobile `grid-auto-rows: 1fr` в контейнере с auto-height выравнивает рамки по наибольшему intrinsic-размеру. Внутренний выбранный ряд заполняет одинаковый остаток; оси выбора не разъезжаются. SPIN находится после grid в нормальном потоке, без абсолютных координат.

Модификатор dense можно назначить по длине строк, без измерения пикселей и без ResizeObserver/canvas. Более простая полностью CSS-альтернатива — всегда использовать 22 desktop / 18 mobile, оставив перенос и автоматическую высоту. Измерение текста JavaScript не требуется. Даже если новые каталоги дадут 4–6 строк, рамки должны вырасти, а не обрезать их.

## 9. Длинный Language и диапазон слов

Сохраняются настоящие native select с видимыми label. На mobile Language всегда full-width. `Portuguese (Brazil)` помещается даже на 320 при 16 px. CEFR поддерживает плюс/минус, например B1+ и B2-, без уменьшения.

Text Length показывает название Short/Medium/Long, а отдельный helper под полем — актуальный объём по [LEVELS_LENGTH.md](../LEVELS_LENGTH.md), например `40–80 words`, `20–60 words`, `4–8 fields` или `16–24 items`. Он зависит от содержательного профиля и формата; старые единые диапазоны описывают только стартовый код. Helper связан с select через aria-describedby, минимум одна зарезервированная строка 20, с ростом по нормальному потоку для переноса. В доступном описании присутствуют объём и единица; после сброса недопустимого результата не показывать диапазон предыдущего формата как актуальный.

Для будущего необычно длинного Language, который всё-таки не помещается в native selected field, его полное выбранное название дополнительно выводится переносимым текстом под Language, без hover-only tooltip. Эта подпись появляется только при явно длинном каталожном названии (>28 символов); не заменять native select сложным dropdown framework. Служебный текст не накладывается на соседние поля.

## 10. Полный prompt, прокрутка, копирование

Базовый вариант сохраняет read-only textarea из текущего приложения; содержимое — полный prompt. По умолчанию высота 180. Просторный режим (dense results **или** `prompt.length > 1000`) — 280 desktop / 220 mobile. Максимум 320 desktop / 280 mobile. Это пороги длины строк, а не измерение текста; они не означают количество слов будущего reading text.

- Desktop: разрешён `resize: vertical` в диапазоне 180–320; ширина не изменяется. Mobile: ручной resize не обязателен, на нём нельзя основывать доступность; заданная высота 180 или 220 и внутренний scroll.
- `overflow-y: auto`; длинные строки и URL переносятся; горизонтальной прокрутки нет. Read-only textarea использует soft wrap, `white-space: pre-wrap` и `overflow-wrap: anywhere`.
- Scrollbar не скрывается. Стабильный gutter резервируется там, где браузер его поддерживает; декоративная бумага не обрезает focus и scrollbar.
- Текст можно выделять мышью и стандартным долгим нажатием на mobile; `user-select: text`, textarea не disabled. Tab переводит фокус в preview; Ctrl/Cmd+A в нём выделяет весь prompt; Ctrl/Cmd+C позволяет скопировать вручную.
- Copy prompt находится **после textarea вне её scroll-контейнера**. Копируется весь prompt, независимо от scroll-позиции и видимого фрагмента.
- Не обрезать строку, которая передаётся Clipboard API, и не копировать демонстрационный текст из PNG. При отказе Clipboard API остаётся ручное выделение.
- Если настройка или комбинация изменена, success от старого prompt скрывается. Сообщение показывается только для строки, которая действительно была скопирована, как уже предусмотрено текущим сравнением `copyStatus.prompt === prompt`.

## 11. How to use

Изначально закрыт. Кнопка справа в utility row; на mobile utility row перед H1. Полный утверждённый текст:

1. Choose your language, level and length.
2. Spin to get a ready-to-use prompt.
3. Paste it into any AI chat to create a text for reading practice.

Desktop: небольшая paper-подсказка max-width 320, padding 16, текст 16/1.5, radius 8, anchored к кнопке, z-index поверх декоративной сцены. Mobile: доступное диалоговое окно с полями 16 от viewport, max-width 358, max-height calc(100dvh−32px), собственный scroll если нужно; кнопка Close 48. Открытие по нажатию/клавиатуре, закрытие Close/Escape, возвращение фокуса в How to use. У модального mobile-диалога нужен корректный focus management. Ни одна инструкция не доступна исключительно по hover. Пока это спецификация, не реализованная функция приложения.

## 12. Состояния и уведомления

Дополнение после согласования уровня и длины: [LEVELS_LENGTH.md](../LEVELS_LENGTH.md) определяет актуальный объём и поведение настроек. При допустимой комбинации промпт меняется сразу, а рядом с заголовком preview в зарезервированном месте появляются галочка и `Prompt updated` на 1600 ms; рамка/фон мягко подсвечиваются за 120 ms и возвращаются за 240 ms. Толщина рамки, размеры и видимость текста не меняются; Copy доступна сразу, фокус остаётся на настройке. В reduced motion подтверждение статическое. При недопустимой комбинации результат и промпт сбрасываются, Copy отключается, пояснение предлагает явный SPIN. Успешное обновление, копирование и ошибка имеют разные тексты; старые async-сообщения не описывают новую версию промпта. Подробная координация эффекта — в [MOTION.md](MOTION.md).

| Состояние | Вид и поведение |
| --- | --- |
| Первоначальный экран | Реальные текущие defaults English / A2 / Short и Daily life / Short story / Unexpected discovery. Prompt уже заполнен; SPIN и Copy активны; help закрыт; зарезервированная status-область пустая |
| После SPIN | Три значения и prompt обновляются вместе, ровно один random selection по активации. Один polite announcement комбинации; соседние декоративные строки aria-hidden |
| Допустимая смена настроек | Комбинация сохранена, prompt сразу адаптирован; галочка `Prompt updated`, короткий акцент блока, одно актуальное polite announcement; без запуска барабанов и блокировки Copy |
| Недопустимая смена уровня/длины | Результат и prompt сброшены; Copy недоступна, SPIN доступна; пояснение причины, без галочки обновления и автоматического выбора |
| Hover SPIN | primary-hover; тот же размер и позиция; применяется только там, где есть hover-capable pointer |
| Hover Copy / Help | Лёгкая paper/ivory tint, неизменная граница; никаких новых действий, доступных только hover |
| Focus-visible | На бумаге 3 px primary outline с offset 3; на тёмном корпусе и SPIN — 3 px ivory outline с offset 3. Если контур светлого поля выходит на бордовый корпус, добавить ivory separation под primary-контуром. Фокус не обрезается chassis/textarea. Все select, SPIN, Copy, Help и Close имеют видимый focus |
| Pressed SPIN | primary-pressed, нижняя тень 1 вместо 4; допустимо translateY(2px) внутри неизменного button-box. Размеры grid не меняются |
| Disabled | Приглушённая fill, сохраняется читаемая надпись; native disabled, без hover и повторного запуска. Disabled не используется без причины |
| Copy pending | Кнопка сохраняет габарит и пишет `Copying…`; временно недоступна для повторного нажатия; status `Copying…` |
| Copy success | Кнопка снова `Copy prompt`; check + `Prompt copied. Paste it into your AI chat.`; success-bg, текст primary; role=status/polite |
| Copy error | Copy снова активна; error-иконка + `Copy failed. Select the prompt and copy it manually.`; текст error на paper; preview остаётся focusable и выделяемым |

Status занимает минимум 44 desktop / **64 mobile**, включая pad; место резервируется даже без текста, чтобы переключение pending/success/error не двигало соседние блоки. На desktop текст слева, на mobile также слева внутри полосы; иллюстративное центрирование полосы в PNG не является правилом для HTML. Иконка и текст дополняют цвет, не заменяют его. Отдельный toast, перекрывающий машинку, не нужен.

Успех сохраняется до изменения prompt или новой попытки копирования; не нужен неожиданный timer. Если prompt изменился во время асинхронного copy, success не описывает текущий новый prompt. Во время copy SPIN/настройки могут оставаться активны; stale-сообщение отфильтровывается по строке.

Для будущей анимации можно показать статическое busy-состояние: `SPINNING…`, disabled SPIN, aria-busy и выбранные текущие значения до атомарного обновления. Полная анимация, timing и её реализация не входят в работу. В существующей моментальной логике искусственный busy-таймер не вводить.

## 13. Проверка узкого экрана 320 px

Расчёт доступной геометрии, не скриншот работающего сайта:

- Page: 320−12×2 = **296**. Внутри корпуса: 296−12×2 = **272**.
- Подпись барабана 56 + gap 8 → окно **208**. Pad результата 10×2 → **188** под текст.
- Language control: 272−12−12−32 под chevron = **216** под значение.
- Два select второго ряда: (272−12)/2 = **130** каждый; названия Medium/Long и B1+/B2- помещаются, диапазон вынесен под поле.
- SPIN и Copy занимают внутреннюю ширину, высоты 56/48; flex/grid не имеют фиксированной минимальной ширины больше доступной.
- Любое увеличение высоты идёт вниз по нормальному потоку; поперечной прокрутки и перекрытия кнопок не требуется. На 320 допустима более длинная страница.

Они не являются измерениями нового Angle `An unexpected change of plans` или актуальных коротких ракурсов. Измерены строки настоящей локальной Georgia Bold с Windows System.Drawing, размер в **пикселях**, greedy wrap по пробелам. GDI и браузер могут различаться; актуальные значения требуют отдельной проверки и не должны обрезаться.

## 14. Реализация без тяжёлой UI-библиотеки

Будущие реальные компоненты: semantic header, native settings form, `dl` для комбинации, native buttons, read-only textarea, status live region и доступный help. Используются CSS Grid/Flex, обычные borders/gradients/shadows и media queries; font-measurement runtime не требуется.

Декоративная сцена, углы корпуса и буквенные клавиши — отдельные визуальные слои с aria-hidden и pointer-events none. При подготовке production assets фон нужно экспортировать без UI-текста, а корпус разбить на боковины/углы и растяжимую середину либо нарисовать эти формы CSS. Это сохраняет внешний вид при auto-height; целиком растягивать PNG с надписями нельзя. ImageGen-макеты не являются готовыми production sprite/assets и не подключаются как единственный интерфейс.

Полезный порядок следующей отдельной реализации: слой фона → responsive layout и реальные контролы → бумажные барабаны → overflow/copy-state → декоративные части. Новые framework, backend, inference API, tracking, remote fonts и hosting не нужны.
