# Reading Roulette — рабочий бриф для motion design

Дата: 2026-10-09. Это промпт, по которому подготовлена [MOTION.md](MOTION.md); не заявление о готовой анимации.

Обязательный актуальный контракт — **Topic × Format × Angle**; [принципы каталогов](../CATALOGS.md). В reference прежняя подпись Tone устарела: третий барабан должен показывать Angle. Выбор ракурса зависит от темы, формата и настроек по правилам [согласованного каталога Angle](../ANGLES.md); независимость результата от декоративного движения не означает независимость трёх каталогов. Полная комбинация и промпт готовятся до начала движения: не задерживать старт Angle ради вычисления и не запускать подбор по остановке других лент. Сохраняются общий старт и последовательные остановки.

Ты — senior motion designer и UI animator. Спроектируй анимацию Reading Roulette на основе утверждённого [дизайна](DESIGN.md) и [референса](references/reading-roulette-evening-study-v09.png). Сохрани тихий вечерний кабинет, бордовую пишущую машинку, бумажные барабаны, матовую бронзу и бирюзовую клавишу SPIN.

Характер движения: вес небольшого механизма, лёгкое сопротивление бумажного валика, последовательная фиксация трёх результатов. Нужен короткий приятный ритуал случайного выбора, после которого удобно читать и копировать prompt. Выразительность строится на ритме и торможении.

Подготовь конкретную спецификацию для React, TypeScript и обычного CSS. Для управления конечной последовательностью допускается встроенный Web Animations API. Новые зависимости, серверные сервисы и тяжёлые animation-библиотеки не нужны.

Обязательно определи:

1. Единый сценарий от нажатия до доступного для копирования результата; точные длительности, направление, смещения и кривые движения.
2. Устройство ленты, отдельные маски декоративных соседей и защиту полностью читаемого выбранного значения.
3. Различия desktop/mobile, сохранение размеров кнопок, перенос длинных строк и общую высоту трёх барабанов.
4. Однократный выбор комбинации в начале SPIN, независимость случайного результата от декоративного движения и атомарное обновление настоящего результата с prompt.
5. Повторное нажатие, copy pending, фоновую вкладку, resize, отмену, unmount, ошибку выбора и отсутствие animation API.
6. Управление клавиатурой, отсутствие чтения промежуточных слов screen reader, reduced motion без искусственного ожидания.
7. Сдержанную систему микропереходов для кнопок, статусов и How to use.
   Дополнение к исходному брифу: по [LEVELS_LENGTH.md](../LEVELS_LENGTH.md) после допустимой смены языка/уровня/длины prompt обновляется немедленно, затем галочка `Prompt updated` на 1600 ms и акцент рамки/фона 120 + 240 ms подтверждают адаптацию; в reduced motion подтверждение статическое. Copy не блокируется. При недопустимой комбинации — сброс и пояснение с явным SPIN, без успешного подтверждения. Эффект не запускает барабаны и не ставит быстрые изменения в очередь.
8. Критерии будущей проверки с явным разделением уже проверенной документации и ещё не проверенной реализации.

Используй реальные каталоги и исходную логику `selectReadingCombination` / `buildPrompt`. Повторы допустимы; результат не следует перебирать ради эффекта «выигрыша». Длинные строки из DESIGN.md — проверочные данные, не разрешение расширить продуктовые каталоги.

Не анимируй фон, лампу, всю машинку, декоративные буквенные клавиши или чтение prompt. Не добавляй звук, вибрацию, конфетти, счётчики или ощущение загрузки от сервера. Показ результата должен завершать движение.

Границы исходного этапа подготовки motion-спецификации: сохранить спецификацию и рабочий бриф в docs/design без изменения исходников, зависимостей, Git history и deployment. Это описание того этапа, а не запрет на последующую согласованную миграцию UI к Topic / Format / Angle. Если точное поведение нельзя гарантировать одним CSS, указать минимальную необходимую координацию в JavaScript и причину. Числовые предположения о движении не являются проверкой работающего сайта.
