# Reading Roulette — спецификация анимации

Дата: 2026-10-09. Статус: motion design специфицирован; затем подготовлен отдельный локальный интерактивный прототип. В основное приложение анимация и новый дизайн ещё не перенесены.

Обязательный продуктовый контракт — **Topic × Format × Angle**, согласно [принципам каталогов](../CATALOGS.md). Прежняя подпись Tone в сохранённых PNG устарела. Каталог из 30 ракурсов и правила совместимости согласованы в [ANGLES.md](../ANGLES.md): ракурс допускается для полного сочетания темы, формата и настроек. Тон, регистр и перспектива входят в инструкции. Это изменение не меняет таймлайн и геометрию трёх барабанов; текущий прототип пока использует стартовые каталоги.

Проверка движения: [локальный прототип](motion-preview/index.html), [запуск и сценарии](motion-preview/README.md), [границы проведённой проверки](motion-preview/VERIFICATION.md). При запущенном Vite: http://127.0.0.1:5173/docs/design/motion-preview/ . Художественные assets в прототипе заменены упрощённым CSS; страница не входит в обычный production build.

Основа: [DESIGN.md](DESIGN.md), [выбранный reference](references/reading-roulette-evening-study-v09.png), [рабочий промпт](MOTION_BRIEF.md). Числовые правила layout, цветов, шрифтов и переносов берутся из DESIGN.md. Этот документ добавляет движение и уточняет блокировку действий во время него.

## 1. Режиссура

Один SPIN — маленький механический ритуал: клавиша поддаётся → бумага набирает ход → Topic, Format и Angle последовательно фиксируются → готовый prompt доступен для копирования.

Движение локальное и направленное вверх. Корпус, заголовок, фон, лампа и буквенная клавиатура неподвижны. Первое открытие страницы без вступительного вращения. Нет idle-loop, звука, вибрации, бликов, конфетти, тряски или параллакса.

Принципы: ощущение веса через разгон; инерция через торможение; ясность через три остановки с одинаковым интервалом; короткое завершение без последующего покачивания. Подвижные слова во время SPIN — декоративная визуализация, а не новые запросы случайного выбора.

## 2. Основной таймлайн

Время отсчитывается от активации SPIN. Общая длительность **1480 ms** на desktop и mobile. Старт барабанов общий: **80 ms**. Три остановки: **1080 / 1280 / 1480 ms**. Интервал **200 ms** позволяет считывать последовательность.

Полная допустимая комбинация и nextPrompt подготавливаются до начала движения. Для вычисления Angle не добавлять задержку его старта и не ждать события остановки Topic / Format: логический выбор выполняется локально, до визуального раскрытия результатов. Последняя остановка Angle — приём последовательного чтения результата, а не время на поиск подходящего ракурса. Поиск новостей и создание изображений происходят позднее во внешнем AI-чате. Фактическую скорость фильтрации полного каталога нужно измерить при внедрении; 80 ms и длительность SPIN не являются гарантированным вычислительным бюджетом. При reduced motion нет искусственного ожидания.

| Время | Событие |
| --- | --- |
| 0 | Синхронный guard от повторного запуска; один выбор следующей комбинации; snapshot настроек; очистка старого copy-status; резерв геометрии |
| 0–60 | Лицевая часть SPIN опускается на 2 px; нижняя грань уменьшается с 4 до 1 px |
| 60–140 | Лицевая часть возвращается; положение layout-box неизменно |
| 80–240 | Все три ленты ускоряются вверх |
| 240–640 | Все три идут с постоянной скоростью |
| 640–1000 | Topic тормозит; остальные продолжают |
| 840–1200 | Format тормозит |
| 1000–1080 | Topic мягко возвращается с превышения на 2 px в точный центр |
| 1040–1400 | Angle тормозит |
| 1200–1280 | Format фиксируется с тем же возвратом 2 px |
| 1400–1480 | Angle фиксируется |
| 1480 | Один commit новой комбинации и полного prompt; снять busy; вернуть доступность настроек и Copy; одно объявление результата |

До последней остановки видимый preview остаётся прежним с пояснением `Spinning… Your current prompt stays below.` в зарезервированной status-области. Старый prompt остаётся выделяемым. Copy временно недоступна, чтобы кнопка не копировала предыдущий текст вместо ожидаемого результата. Визуально остановившиеся барабаны не вызывают частичного обновления prompt.

После commit текст textarea заменяется сразу, без посимвольного набора, fade-out и декоративной «печати». Прокрутка preview возвращается к началу только при реальном изменении строки. Страница не прокручивается автоматически. Если итоговая строка совпадает с предыдущей, не сбрасывать выделение/scroll preview.

## 3. Точное движение ленты

Каждый барабан имеет конечную вертикальную ленту. Один шаг **S** равен высоте центральной ячейки результата, включая её внутренние поля; S зависит от responsive layout, переносов и доступности. Это не фиксированное число пикселей для всех экранов.

| Барабан | Длительность после старта | Разгон Ta | Равномерный ход Tc | Торможение Tb | Фиксация Ts | Пройдено N ячеек |
| --- | --- | --- | --- | --- | --- | --- |
| Topic | 1000 ms | 160 | 400 | 360 | 80 | 4 |
| Format | 1200 ms | 160 | 600 | 360 | 80 | 5 |
| Angle | 1400 ms | 160 | 800 | 360 | 80 | 6 |

Разгон: квадратичная функция `u²`, CSS cubic-bezier(0.333333, 0, 0.666667, 0.333333). Постоянный ход: linear. Торможение: `1−(1−u)³`, CSS cubic-bezier(0.333333, 1, 0.666667, 1). Фиксация: cubic-bezier(0.4, 0, 0.2, 1). Здесь u — нормализованное время отдельной фазы 0…1.

Дистанция до конца торможения **D = N×S + 2 px**. Распределить её по фазам, чтобы скорость на стыках разгона/хода/торможения совпадала:

```text
denominator = Ta/2 + Tc + Tb/3
Da = D × (Ta/2) / denominator
Dc = D × Tc / denominator
Db = D × (Tb/3) / denominator

Начало             y = 0
Конец разгона      y = −Da
Конец хода         y = −(Da + Dc)
Конец торможения   y = −(N×S + 2px)
Конец фиксации     y = −N×S
```

Для Topic доли D: 2/15, 10/15, 3/15. Для Format: 1/10, 3/4, 3/20. Для Angle: 2/25, 4/5, 3/25. Значения в сумме дают 1. Возврат на 2 px — один небольшой обратный ход; нет пружинной серии колебаний.

Кривые и числа — исходная режиссёрская настройка. Ощущение скорости нужно проверить в браузере; это не измеренный fps. На первой реализации допустима одна настройка длительности по результатам просмотра, с обновлением документа.

### Содержимое ленты

N+3 равных ячеек: верхний сосед, текущий результат, N−1 промежуточных значений, заранее выбранный финальный результат, нижний сосед. Текущий результат имеет индекс 1, финальный — N+1. В начале индекс 1 находится в центре, в конце — N+1.

Промежуточные подписи циклически берутся из соответствующего существующего каталога. Не выдумывать новые темы, не генерировать случайное значение на каждом кадре. Соседние ячейки могут повторяться. Совпадение финального результата с текущим не отменяет выбранную комбинацию: проходит обычный короткий ритуал.

Все ячейки выровнены по центру, имеют одинаковый S, используют размеры/переносы DESIGN.md. Двигается transform всей ленты; React не обновляет слова на каждом кадре. Не применять blur/filter к буквам или scaleY/rotateX к выбранному тексту.

## 4. Окно, маски и слои

Функционально это бумажный валик за неподвижной рамой. Центральная область остаётся читаемой; верхний и нижний декоративные соседи уходят за край.

Слои снаружи внутрь:

1. Бордовый корпус и бронзовая рамка. Неподвижны; не обрезают внешний focus контролов.
2. Paper-подложка барабана. Неподвижна.
3. Локальное окно ленты: центральный результат плюс соседние полосы. Только здесь `overflow: clip`, допустимый fallback `hidden`.
4. Движущаяся лента, aria-hidden, pointer-events none.
5. Неподвижные paper-градиенты исключительно в верхней и нижней соседних полосах. Pointer-events none, aria-hidden.

Верхняя/нижняя соседняя полоса **g = 24 px desktop, 18 px mobile** из DESIGN.md. Маска каждой такой полосы: paper → transparent сверху и transparent → paper снизу; длина градиента равна g. Центральная область имеет **нулевое затемнение**. Маски не заходят на padding выбранного текста. Переход от закрытого внешнего края к полностью прозрачному внутреннему — линейный.

Не накладывать единый `mask-image` с процентными stops на весь барабан: при росте выбранного результата он способен затронуть текст. Рекомендуемый baseline — две отдельные абсолютные gradient-плашки внутри соседних полос; CSS mask не обязателен. При отсутствии gradients остаются clipping и читаемый центральный результат.

Текущая и финальная полные подписи в покое не обрезаются. При движении подпись естественно пересекает границу окна; после остановки весь финальный текст находится в центральной безопасной области. Названия Topic/Format/Angle не входят в ленту, не движутся и не маскируются. На mobile неподвижная подпись слева расположена вне окна справа.

## 5. Геометрия и длинные значения

Нельзя двигать ленту с шагом, рассчитанным на одну строку, если результат занимает три строки. S задаётся реальной центральной областью и сохраняется на протяжении одного SPIN.

В prepare до старта лент:

1. Собрать текущую, будущую и промежуточные подписи всех трёх лент.
2. Если любая из них длиннее 28 символов, включить единый dense на время вращения и для его результата: 22 px desktop / 18 px mobile, line-height 1.25. Не уменьшать ниже минимума DESIGN.md.
3. В центральном sizing-слое каждой рамки наложить невидимые копии участвующих подписей через CSS Grid в одну ячейку. `visibility: hidden`, aria-hidden, без интерактивных элементов. Они участвуют в intrinsic sizing; абсолютное позиционирование для этих копий не подходит.
4. Применить одинаковые wrapping/padding/font к sizing-копиям и ленте. Desktop stretch и mobile `grid-auto-rows: 1fr` согласуют высоты между барабанами.
5. Полученный размер держать неизменным до конца SPIN. В финале сохранять sizing-envelope текущего вращения: удаление визуальной ленты не должно схлопнуть рамки. Envelope заменяется при следующем SPIN либо при изменении viewport.

Если новая длинная подпись требует больше места, допустимо **одно согласованное увеличение** рамок в prepare, до движения. SPIN и preview тогда сдвигаются в нормальном потоке один раз; это необходимый рост контента, а не анимация их координат. Не обещать отсутствие layout shift при появлении текста любой длины. После начала движения и при финальном commit новых скачков быть не должно. Height/max-height не анимировать. В рамках будущего browser QA отдельно оценить переход short → long.

После long → short барабаны могут остаться просторнее до следующего prepare; это предпочтительнее сжатия сразу после остановки. Короткий итог может сохранить dense-размер в таком вращении. Это явное уточнение статического DESIGN.md для переходного состояния, а не бесконечное shrink-to-fit.

Все подписи переносятся по словам, `overflow-wrap: anywhere`; нет line-clamp, ellipsis или truncation. Даже четыре–шесть строк должны участвовать в расчёте S. Максимального числа строк нет.

### Как обойтись без измерения шрифта JavaScript

Sizing-слой определяет центральную высоту H = S обычным CSS. Внутри него absolute-лента начинается на `top: -100%`, содержит N+3 ячеек и имеет высоту `(N+3)×100%` центрального контейнера. Каждая ячейка равна H; внешний clip включает соседние полосы g по краям. Так ячейка с индексом 1 начинает в центре.

Для transform ленты один шаг равен `100/(N+3)%` её собственной высоты. Формулы из раздела 3 переводятся в проценты ленты; превышение 2 px добавляется через calc(). Число N известно заранее. Не использовать translateY(−100%) как один шаг всей многострочной ленты.

JavaScript нужен для состояния, выбранного результата, управления конечной последовательностью и отмены. Canvas/font measurement/ResizeObserver для определения переносов не требуются. В первой вёрстке проверить процентные containing blocks; если CSS-структура не обеспечивает определённую высоту ленты, допустимо одно чтение размера центрального окна перед стартом, с документированной причиной. Не измерять каждый кадр.

## 6. Desktop, mobile и изменение размеров

На ≥640 px остановки читаются слева направо; на <640 — сверху вниз. Направление движения ленты вверх, длительности, N и превышение 2 px одинаковы. В mobile нет декоративных буквенных клавиш, дополнительные вращающиеся шестерни не добавляются.

Размеры контролов и font minima не меняются ради движения. На 320 px сохраняются внешние поля 12, высоты SPIN 56 и Copy 48. SPIN остаётся обычным элементом потока, не sticky. Маски ограничены каждым правым окном и не затрагивают боковую подпись.

При реальном resize окна, смене ориентации или responsive breakpoint в процессе — завершить текущее вращение мгновенно выбранным результатом, убрать transforms и пересчитать обычный auto layout. Не продолжать путь с устаревшим S. На mobile показ/скрытие адресной строки, меняющее только visual viewport height, не является поводом завершения: layout зависит от ширины. Не добавлять обработчик на каждый scroll.

## 7. Контракт состояния

```text
idle → prepare → spinning → commit → idle
                   ↓
          immediate commit on interruption

prepare selection error → idle with error; previous valid result preserved, otherwise empty
unmount → cleanup only, no commit
```

Один запуск создаёт `spinId`, snapshot настроек и nextCombination. `selectReadingCombination()` вызывается один раз на принятую активацию. В текущих стартовых каталогах внутри три draw — Topic, Format, затем Angle из явно допустимых для выбранного формата. Будущая полная выборка учитывает содержательные профили, длину, совместимость и веса семейств; число внутренних draw не фиксируется. Это условный выбор, а не независимая выборка из всех трёх каталогов. Декоративные кадры и остановки отдельных лент не вызывают эту функцию и не влияют на вероятность результата. Полный nextPrompt собирается тем же `buildPrompt` из snapshot и nextCombination до начала движения; пустой допустимый набор обрабатывается как ошибка до анимации успешного результата.

До commit настоящие combination/prompt — предыдущие. Остановившиеся отдельные ленты визуально показывают будущие значения, но скрыты от accessibility tree; экран помечен busy. На commit вся комбинация и prompt меняются одним согласованным обновлением состояния; не собирать промежуточный prompt из нового Topic и старых Format/Angle.

| Элемент | Во время SPIN |
| --- | --- |
| SPIN | Надпись `SPINNING…`, та же ширина; aria-disabled=true и синхронная защита handler |
| Настройки | native disabled до commit; значения видимы, контраст не ниже правил DESIGN.md |
| Copy prompt | native disabled + доступное описание ожидания; отдельная проверка busy в handler |
| Preview | Предыдущий полный текст; readOnly, selectable, не disabled; пользователь может вручную скопировать старый prompt |
| How to use | Остаётся доступным; открытие не запускает и не перезапускает движение |

Для SPIN используется aria-disabled вместо native disabled, чтобы инициировавшая клавиатурой кнопка могла сохранить фокус. Это точечное уточнение DESIGN.md. Native button остаётся button, Enter/Space вызывают тот же guarded handler. В busy повторные клики/Enter/Space игнорируются, не ставятся в очередь. После завершения фокус не переносится в preview автоматически; если пользователь ушёл в Help, его не возвращать к SPIN.

В начале SPIN старый copy-status скрывается. Copy pending, начатый до SPIN, может технически завершиться в браузере, но его запоздавший success/error не заменяет текущую spin-индикацию: проверять id попытки и актуальность prompt. Одного равенства строк недостаточно, если повторилась та же комбинация. После SPIN success появляется только по новой явной попытке Copy.

Без SPIN изменение настроек следует [LEVELS_LENGTH.md](../LEVELS_LENGTH.md): допустимая комбинация сохраняется, prompt сразу пересобирается и получает короткое подтверждение адаптации; недоступные комбинация и prompt сбрасываются, Copy отключается, предлагается явный SPIN. Настройки не запускают барабаны. После окончания SPIN они снова активны. Эти фильтры и подтверждение предстоит перенести в приложение и прототип; текущий код сохраняет комбинацию без проверки допуска.

### Подтверждение адаптации промпта

После смены языка, уровня или длины, когда комбинация допустима и готовая строка изменилась, текст обновляется сразу. Рядом с заголовком preview в зарезервированной области появляются галочка и `Prompt updated` на **1600 ms** от последнего обновления. Рамка/фон блока получают мягкий акцент: **120 ms** появление и **240 ms** возврат к обычному виду. Толщина рамки и размеры не меняются; сам текст остаётся видимым, без fade, набора по буквам и перемещения. Фокус остаётся на настройке, страница не прокручивается. Это подтверждение локального обновления, а не загрузка или copy-success; искусственного pending, aria-busy или блокировки Copy нет.

Быстрые изменения заменяют эффект и перезапускают один таймер, без очереди; устаревшие callback не скрывают новое подтверждение. Начало SPIN, сброс недопустимого результата и unmount отменяют эффект/таймер. Старый copy-status очищается при изменении prompt, запоздалый clipboard callback фильтруется по актуальной ревизии и ID. Через существующую polite live-region даётся одно актуальное объявление обновления; декоративная галочка не читается отдельно. При первоначальном render, неизменном тексте, ошибке или недопустимом сочетании успех не показывается.

В reduced motion галочка и текст появляются статически на те же 1600 ms, без анимированной подсветки; функциональность доступна сразу. Ошибка animation API также оставляет статическое подтверждение. Это требования будущей реализации; длительности не объявляются проверенными в браузере.

## 8. Reduced motion и восстановление

При `prefers-reduced-motion: reduce` — один random selection и немедленный атомарный commit, без движения лент, превышения, кнопочного translate или искусственной паузы 1480 ms. Статическое изменение цвета pressed допустимо. Не мигать промежуточным `SPINNING…` на один кадр. Функциональность и вероятность те же. Настройка пользователя читается до запуска, а её включение в процессе завершает активный SPIN сразу.

| Ситуация | Решение |
| --- | --- |
| Документ стал hidden | Commit заранее выбранного результата сразу; не оставлять анимацию ждать возврата и не выбирать снова |
| Активация в уже hidden документе | Мгновенный путь без анимации |
| Resize / смена ориентации | Мгновенный commit и обычный responsive layout |
| Animation API отсутствует / ошибка запуска | Мгновенный commit; приложение остаётся полезным |
| Ошибка выбора / buildPrompt во время SPIN | Сохранить прежний допустимый результат либо пустое состояние после сброса, снять busy; `Could not spin. Please try again.` в status; никаких undefined и восстановления недопустимого prompt |
| Unmount / dev cleanup | Отменить animations/listeners/watchdog, пометить spinId неактуальным; не setState и не выбирать заново |
| Пропущенный finish / зависшее ожидание | Защитный watchdog 2000 ms от принятия SPIN: commit подготовленного результата, без нового draw |

Каждый commit идемпотентен по spinId: finish, watchdog, resize и visibilitychange не могут закоммитить его дважды. Отмена декоративной анимации сама по себе не означает отмену выбранного результата. При unmount завершение не применяется.

Предпочтительный механизм — один набор конечных WAAPI-анимаций; задержка каждой 80 ms, длительности 1000/1200/1400. Ожидать завершение всех трёх и затем commit. По завершении брать финальную DOM-геометрию из статического render; убрать filling-effects через cancel без визуального отката. Обработать отклонение finished Promise при cancel. Таймер 1480 не является единственным механизмом завершения; watchdog только страховка.

## 9. Доступность и чтение

Семантический результат — одна стабильная dl/область; во время SPIN она хранит предыдущие значения с aria-busy. Декоративная лента, маски, sizing-копии и соседи всегда aria-hidden. Удаление видимого статического текста на время анимации не должно скрывать семантическую область через visibility:hidden.

Одна отдельная status live region сообщает старт `Spinning…` и итог `New combination: Travel. Dialogue. Unexpected discovery. Prompt ready.` с настоящими названиями. Busy-helper в preview не создаёт второе объявление. Результирующая dl не дублирует объявление через собственный aria-live; это уточнение текущего App.tsx. В reduced mode — только итог. Textarea не делать live region. Новые длинные значения не сокращать в доступном тексте.

Стартовая status-строка и итог используют резерв 44 px desktop / 64 px mobile как минимум; длинные названия для screen reader можно вынести в visually-hidden часть итогового сообщения, оставив видимое `Prompt ready. Copy it to your AI chat.`. При увеличении шрифта status имеет auto-height; резерв не означает фиксированный clipping-box.

Focus остаётся видимым и вне clip масок. Keyboard Tab-order следует settings → SPIN → preview → Copy → help согласно фактической DOM-композиции (help в header допускает естественный ранний Tab); не вводить положительные tabindex для подгонки. Screen reader получает финальные данные один раз, не слова вращающейся ленты.

## 10. Остальные микропереходы

| Элемент | Движение / длительность |
| --- | --- |
| Hover SPIN / Copy / Help | 120 ms, ease-out, только цвет background/border; без роста и прыжка |
| Focus-visible | Контур появляется немедленно; без fade |
| Pressed SPIN | 60 ms вниз 2 px + 80 ms возврат; easing cubic-bezier(0.2,0,0,1); reduced mode только цвет |
| Pressed Copy / Help | Изменение заливки немедленно; без translate |
| Copy pending/success/error | Текст меняется сразу в зарезервированной области, без sliding/toast и танцующей галочки |
| Prompt updated после настроек | Текст prompt обновляется сразу; акцент рамки/фона 120 ms появление + 240 ms возврат; статическая галочка и надпись 1600 ms, без сдвига layout; reduced mode без анимации |
| Help open/close | 100 ms opacity 0→1 / 1→0; геометрия и scale неизменны; reduced mode мгновенно |
| Новая бумага / prompt | Без выезда листа, auto-type и скрытия текста |

Для help фокусирование/возврат и modal semantics должны работать независимо от opacity-анимации. Закрытие не ждёт transitionend для восстановления функционального состояния. Нет бесконечных вращающихся иконок; repeat-иконка на SPIN остаётся статичной.

## 11. Приёмка будущей реализации

Первый рабочий просмотр: существующий выбранный UI с одной действующей анимацией SPIN. Не подключать неподвижный mockup PNG вместо контролов. Сначала функциональная последовательность и корректные данные, затем градиентные края и декоративная детализация.

Обязательные проверки:

- 1440 / 1024 / 768 / 640 / 390 / 320 px; короткие Travel/Dialogue/Unexpected discovery и актуальные длинные fixtures из DESIGN.md; переход short→long и long→short.
- Topic/Format/Angle останавливаются в 1080/1280/1480 ms в нормальном активном документе; погрешность планирования browser frames допустима, задержка результата после последней остановки не добавляется.
- Во время движения S одинаков между барабанами; на commit центр не дёргается, masks не закрывают буквы, шесть строк увеличивают область вместо обрезки.
- За один запуск только один выбор полной допустимой комбинации до начала движения; промежуточные подписи и остановки лент не вызывают подбор Angle и не меняют product state. Три draws относятся к текущим стартовым каталогам, а не к будущему алгоритму с весами и фильтрами. Повтор той же комбинации разрешён.
- 10 быстрых кликов/Enter не создают очередь; focus остаётся доступным; Copy не выдаёт старый prompt за новый; запоздавший clipboard callback не заменяет spin-status.
- Resize, hidden tab, reduce включён до и во время SPIN, unmount, отсутствие WAAPI, отказ clipboard и выбор из невалидного каталога не оставляют busy навсегда.
- Финальный preview и Clipboard API получают один и тот же полный buildPrompt; manual select работает; при одинаковом итоге preview scroll не сбрасывается.
- После допустимой смены языка/уровня/длины промпт обновляется до эффекта, Copy доступна сразу, `Prompt updated` соответствует последней ревизии; быстрые изменения, SPIN, ошибка, сброс результата и unmount не оставляют старые эффекты или таймеры. В reduced motion есть статическое подтверждение. Новое состояние не сдвигает блоки на 320 px и при zoom.
- Клавиатура, screen reader, 200% zoom, font fallback, касание на mobile; один итоговый announcement, никаких промежуточных слов.
- Performance trace: движение через transform, без React render на кадр, регулярного layout measurement и растрового blur; читаемый idle после удаления animation-effects.

Это критерии приёмки, **не выполненные тесты**. При подготовке спецификации проверены исходные контракты, логика таймлайна, суммы дистанций, локальные ссылки и неизменность исходников/референса. Впоследствии создан отдельный прототип; его фактические проверки перечислены в VERIFICATION.md, а просмотр живого движения, Clipboard и accessibility QA остаются непроверенными из-за недоступности автоматического подключения браузера.

## 12. Источники для будущей реализации

Технические ограничения сверены с первичной документацией, 2026-10-09:

- [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion) — предпочтение уменьшенного движения; немедленный результат здесь является нашим продуктовым решением.
- [MDN: Animation.finished](https://developer.mozilla.org/en-US/docs/Web/API/Animation/finished) и [Animation.cancel](https://developer.mozilla.org/en-US/docs/Web/API/Animation/cancel) — ожидание завершения и обработка отмены.
- [MDN: overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow) — локальное обрезание ленты; не глобальное скрытие переполнения страницы.
- [MDN: CSS mask properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Masking/Mask_properties) — разделение маски и clipping; отдельные соседние gradient-плашки выбраны для защиты центра.

Тайминг, ритм, кривые, амплитуда и маски — собственные дизайн-решения Reading Roulette. Готовых production assets, анимационного видео и реализации этот документ не содержит. Открытых вопросов, требующих выбора пользователя перед техническим прототипом, нет.
