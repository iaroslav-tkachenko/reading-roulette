## 1. Режиссура: живые механические слоты

2026-10-10: пользователь принял вращение барабанов упрощённого v2-прототипа как основу. Этап 2 подготовки [раздельных художественных assets](ASSETS.md) выполнен; анимации на финальном оформлении подключены в основном React-интерфейсе на этапе 3. Это уточняет порядок работ, не меняет тайминги ниже и не является автоматической browser-проверкой.

Полная desktop-клавиатура восстановлена по просьбе пользователя: 19 декоративных круглых клавиш, QWERT / ASDFG слева и YUIOP / HJKL справа. Ниже «четыре клавиши» означает четыре движущиеся Q/S/O/J внутри этого полного набора; остальные клавиши остаются видимыми. Редкая клавиатура из четырёх элементов не является утверждённым оформлением.

Нажатие должно ощущаться сразу: эмалевая клавиша заметно уходит вниз, механизм включается, десятки подписей проходят через окна. Topic фиксируется, пока Format и Angle ещё быстро вращаются. После Format последний Angle продолжает быстрый ход и только затем тормозит. На последней остановке машинка успокаивается, появляется готовый prompt.

Праздничность выражают скорость, три чётких остановки, движение боковых колёс и короткая волна декоративных клавиш. Движение фона, лампы и всей страницы не требуется. Не трясти текст, корпус или камеру. Фон остаётся спокойным; буквы в итоговом результате и prompt читаются устойчиво.

Барабаны стартуют одновременно, все ленты идут вверх. Первое открытие без автоматического SPIN. Нет бесконечного idle-движения. Звук, вибрация, конфетти и новые функции не входят в этот этап.

Основной UI, типы, buildPrompt, селектор и локальный прототип используют Angle. В коде пока **3 Topic / 3 Format / 4 Angle**, совместимость через format.angleIds, прежние единые диапазоны длины. Контентный профиль отличается от профиля весов. A2- использует содержательный профиль A1, B1- — A2, B2- — B1, C1- — B2; языковая инструкция сохраняет выбранный уровень. Например, A2- получает веса группы A2, но допуск содержания A1. Веса не подменяют минимумы Topic/Format/Angle. Long и картинка не повышают допустимую сложность.

Полная допустимая комбинация и prompt готовятся **один раз до движения**. Angle логически условен, но его вычисление не ждёт остановки Topic/Format. Пролетающие подписи не вызывают повторную выборку. Три draw описывают стартовый код, а не ограничивают будущую взвешенную выборку.

## 3. Таймлайн v2

Полный цикл **2440 ms (2.44 s)** на desktop и mobile. Общий старт лент **100 ms** после принятой активации. Остановки **1480 / 1960 / 2440 ms**, интервал **480 ms**.

| Время от активации | Событие |
| --- | --- |
| 0 | Guard, snapshot настроек, подготовка допустимой комбинации и prompt, очистка прежних эффектов и copy-status |
| 0–60 | Лицевая часть SPIN опускается на 4 px desktop / 3 px mobile; нижняя грань 4 → 1 px |
| 60–220 | Клавиша возвращается; ленты уже набирают скорость |
| 100–240 | Общий разгон всех барабанов |
| 240–1140 | Все три быстро вращаются с почти одинаковой скоростью около 15 ячеек/s |
| 1140–1400 | Тормозит только Topic; Format и Angle ещё идут на полной скорости |
| 1400–1480 | Topic фиксируется с небольшим возвратом |
| 1480–1620 | Topic неподвижен, оба оставшихся барабана всё ещё быстрые |
| 1620–1880 | Тормозит Format; Angle продолжает полный ход |
| 1880–1960 | Format фиксируется |
| 1960–2100 | Topic и Format неподвижны, Angle ещё идёт на полной скорости |
| 2100–2360 | Тормозит Angle |
| 2360–2440 | Angle фиксируется, завершаются вспомогательные движения |
| 2440 | Атомарный commit результатов и prompt, снятие busy, доступное копирование |

Не начинать торможение всех лент одновременно. Последовательность должна читаться даже без знания таймингов: «один уже встал — другие ещё крутятся быстро». Движение длинных подписей сохраняет тот же ритм и количество позиций.

Числа — исходная настройка для будущего просмотра, не результат browser QA. Полный подбор комбинации не использует 100 ms или длительность SPIN как вычислительный бюджет. Если подготовка не успевает, сначала завершить подготовку и только затем начать общий визуальный отсчёт; не компенсировать медленную фильтрацию задержкой одного Angle. Измерить фактическую подготовку при внедрении, не добавлять искусственный pending.

## 4. Скорость, число позиций и кривые

S — высота центральной ячейки с переносами и padding, одинаковая у трёх барабанов в одном вращении. N — число пройденных позиций, **не число уникальных записей каталога**. Повторы разрешены.

| Барабан | Длительность от общего старта | Разгон Ta | Быстрый ход Tc | Торможение Tb | Фиксация Ts | N |
| --- | --- | --- | --- | --- | --- | --- |
| Topic | 1380 ms | 140 | 900 | 260 | 80 | 16 |
| Format | 1860 ms | 140 | 1380 | 260 | 80 | 23 |
| Angle | 2340 ms | 140 | 1860 | 260 | 80 | 30 |

Ta+Tc+Tb+Ts равно длительности строки; плюс 100 ms даёт остановки 1480/1960/2440. Во время равномерного хода скорость примерно **15.14 / 14.97 / 14.88 S/s** без учёта малого превышения. Это расчёт дистанции, не обещание fps.

Разгон u²: cubic-bezier(0.333333,0,0.666667,0.333333). Быстрый ход: linear. Торможение 1−(1−u)³: cubic-bezier(0.333333,1,0.666667,1). Возврат: cubic-bezier(0.4,0,0.2,1).

Превышение δ = **3 px desktop / 2 px mobile**, один возврат за 80 ms, без серии пружинных колебаний. Распределение дистанции сохраняет скорость на стыках:

```text
D = N × S + δ
denominator = Ta/2 + Tc + Tb/3
Da = D × (Ta/2) / denominator
Dc = D × Tc / denominator
Db = D × (Tb/3) / denominator

Начало            y = 0
Конец разгона     y = −Da
Конец хода        y = −(Da + Dc)
Конец торможения  y = −(N × S + δ)
Конец фиксации    y = −N × S
```

Двигается transform всей ленты; нет React render на каждый кадр, текстового scramble, scaleY, rotateX и фильтра blur на буквах. На быстром ходу отдельные слова могут быть нечитабельны из-за скорости; после фиксации весь результат должен быть читаемым.

## 5. Какие слова пролетают

Для каждой ленты подготовить N+3 равных ячейки: верхний сосед, текущий результат, N−1 промежуточных, финальный результат, нижний сосед. Индексы текущего и финального — 1 и N+1. Декоративный порядок строится один раз до старта.

Слова берутся из реальных **допустимых для выбранных настроек** пулов; недопустимые по профилю или длине записи не использовать как приманку. Angle-пул содержит совместимые с подготовленными Topic/Format ракурсы. Эти подписи — декор, не обещание, что каждый промежуточный набор трёх окон является готовой комбинацией.

При маленьком пуле повторять его с изменением начального смещения; избегать одинаковых соседей, когда есть альтернатива. Это не запрет повторов результата и не новая вероятность. Если доступен один вариант, допустим его повтор: не выдумывать дополнительные слова ради скорости. При будущем большом каталоге использовать разнообразный срез допущенных коротких labels; не вставлять инструкции prompt в ленту.

N=16/23/30 означает больше пролетающих позиций по сравнению с v1 (4/5/6), но не гарантирует 16/23/30 разных слов в стартовых каталогах. Порядок декора не вызывает продуктовый селектор и не влияет на итоговый случайный выбор.

## 6. Вторичное движение машинки

Все детали ниже декоративны, aria-hidden, pointer-events none, без tabindex и признаков самостоятельных действий.

| Деталь | Требование v2 |
| --- | --- |
| Лицевая часть SPIN | Видимый ход 4/3 px и изменение нижней грани; текст и иконка движутся с лицевой частью, внешний focus-контур неподвижен |
| Боковые колёса/оси desktop | Левое связано с Topic, правое — с Angle. Поворот на 540° / 900° по нормализованному ходу соответствующей ленты; активное вращение заканчивается в конце её торможения, при фиксации ось уже неподвижна |
| Декоративные круглые клавиши desktop | Четыре клавиши, по две с каждой стороны. Волна нажатий на 1.5 px с задержками 0/90/180/270 ms; отдельный ход 160 ms вниз-и-назад; повтор волны каждые 520 ms только во время SPIN |
| Завершение волны | Начать первую волну в 240 ms; последнюю новую волну не позднее 1800 ms, чтобы все клавиши вернулись до финала; не обрывать их в утопленном положении |
| Маленький механический язычок mobile | Если нужен заменитель убранной клавиатуры — один встроенный в корпус элемент не более 12×6 px, колебание ±1 px с периодом 260 ms в фазе быстрого хода; к 2440 ms точно в исходном положении |
| Финальный акцент | Один мягкий акцент существующей рамки окон: 120 ms появление + 180 ms возврат, заканчивается к 2440 ms. Запускается в 2140 ms; не меняет толщину рамки или текст |
| Фон, лампа, заголовок, корпус и prompt | Неподвижны; лампа не мигает, бумага не выезжает, prompt не печатается по буквам |

Колёса получают тот же прогресс разгона/хода/торможения, что соответствующая лента, без обратного возврата на финальной фиксации текста. Вращение оси завершается на конце торможения, затем остаётся неподвижным. Декоративная клавиатура двигается только в принятом SPIN; hover по ней ничего не делает.

На mobile колёса и буквенные клавиши скрыты как в DESIGN.md; ради них не расширять габариты. Язычок допустим только внутри существующего корпуса, без дополнительной строки/контрола. Главные акценты на телефоне — ход SPIN и три быстрые ленты. Число вторичных деталей уменьшается, скорость и ритм основных остаются.

Для нажатия разделить неподвижный button-box/focus и подвижную лицевую часть. Pointerdown показывает pressed сразу, до тяжёлой подготовки. Отмена pointer до активации возвращает клавишу без SPIN. Клавиатурная активация получает тот же ход. В busy повторные нажатия не запускают новые волны или повторный SPIN.

Требуется раздельная структура assets: корпус, колёса/оси, выбранные keycaps и лицевая часть SPIN. Единый PNG всей машинки не позволяет корректно анимировать эти части; отдельные CSS/SVG-слои готовятся на этапе реализации. Новые bitmap-изображения сейчас не создавались.

## 7. Маски, текст и геометрия

Неподвижная рама содержит отдельное окно ленты. Только окно использует overflow: clip (fallback hidden). Над ним две отдельные paper-gradient полосы **24 px desktop / 18 px mobile**, скрывающие декоративных соседей. Центр выбранного результата не затемняется. Labels Topic/Format/Angle и focus находятся вне clip/mask.

В prepare собрать текущую, будущую и промежуточные подписи. Общий dense включается при любой строке >28 символов: 22 px desktop / 18 px mobile, line-height 1.25. Невидимые aria-hidden sizing-копии в одной CSS Grid-ячейке определяют необходимый S; учитываются все участвующие подписи, а не весь неограниченный каталог. Desktop stretch и mobile grid-auto-rows:1fr согласуют три рамки.

Выбранный текст полностью переносится; нет ellipsis/line-clamp или бесконечного уменьшения. Сначала достаточная ширина, затем ограниченный dense, затем рост высоты. Четыре–шесть строк также должны помещаться. Одна согласованная адаптация высоты допустима в prepare до старта; с 100 до 2440 ms и на commit геометрия не меняется. Сохранять sizing-envelope после остановки; пересмотреть его на следующем SPIN или resize, а не схлопывать сразу.

Пролетающие ячейки могут пересекать края окна; финальная полностью находится в центральной безопасной зоне. Не сокращать итоговый Angle ради того, чтобы во время быстрого хода он читался за один кадр.

Процентный шаг: лента имеет N+3 ячеек, высоту (N+3)×S; один S равен 100/(N+3)% высоты самой ленты. Как в v1, начальное top:−100% относится к центральному контейнеру S. JS нужен для координации состояния, а не измерения букв. Если фактическая CSS-структура требует числового S, допустимо одно чтение размера перед стартом; не измерять каждый кадр.

На ≥640 px остановки читаются слева направо, ниже — сверху вниз. На 320 сохраняются поля 12 px, SPIN высотой 56 и Copy 48. Нет глобального overflow-x:hidden для сокрытия ошибок. Новые детали не перекрывают настройки, результаты и preview.

## 8. Результат, состояния и копирование

idle → prepare → spinning → commit → idle. Snapshot настроек и вся nextCombination/nextPrompt готовы до движения. На отдельных остановках меняется только видимый декоративный слой; семантический результат и preview до финала остаются прежними. В 2440 ms результат и полный prompt обновляются атомарно.

SPIN: SPINNING…, неизменный размер, aria-disabled и синхронный guard с сохранением фокуса. Настройки и Copy временно native disabled. Preview остаётся readOnly и выделяемым; старый текст можно вручную скопировать. How to use доступна. Повторные клики/Enter/Space не ставятся в очередь.

Старт убирает старые copy/Prompt updated эффекты, отменяет их таймеры. Использовать spinId, promptRevision и copyAttemptId: равенства строк недостаточно при повторе комбинации или возврате к прежним настройкам. Запоздалый clipboard callback не заменяет spin-status. Copy после commit получает весь актуальный buildPrompt независимо от scroll preview.

Busy-сообщение: Spinning… Your current prompt stays below. После финала: Prompt ready. Copy it to your AI chat. Статус занимает минимум 44 px desktop / 64 mobile с auto-height. Один polite announcement результата; декоративные ленты, соседи, клавиши, маски и sizing-копии не читаются screen reader.

Prompt не fading/typing. При реально новой строке scroll preview возвращается к началу; при той же строке не сбрасывать выделение/scroll. Размеры и внутренний scroll — DESIGN.md; структурные и source/image инструкции — утверждённые контентные документы, не старый универсальный шаблон «only reading text».

## 9. Изменение настроек — отдельный спокойный сценарий

По LEVELS_LENGTH.md допустимая комбинация сохраняется, prompt и helper меняются сразу. Галочка Prompt updated на 1600 ms и акцент рамки/фона 120 ms + 240 ms подтверждают обновление; Copy остаётся доступной. Нет SPIN, барабанов, боковых колёс или клавиш ради смены настройки.

Если новые уровень/длина запрещают сочетание, сбросить всю комбинацию и prompt, отключить Copy и предложить явный SPIN. Не выбирать замену автоматически и не показывать успешное Prompt updated. Изменение языка не меняет семантические каталоги. Переключение только положительных весов не сбрасывает допустимый результат.

Helper зависит от содержательного профиля и модели формата: words, fields или items. Long не растягивает короткую записку; до допустимого результата не показывать старый форматный диапазон. Для языков с неоднозначным счётом слов использовать утверждённые структурные ограничения без выдуманных диапазонов знаков.

Быстрые изменения заменяют единственный эффект/таймер без очереди. Неизменная строка и initial render не вызывают подтверждение. Сброс, ошибка, SPIN и unmount очищают устаревшие эффекты. Live-region сообщает актуальное обновление один раз, без чтения всего prompt.

## 10. Reduced motion, отмена и устойчивость

prefers-reduced-motion:reduce — немедленный атомарный результат после проверки допуска, без ожидания 2440 ms, лент, хода кнопки, колёс, волны клавиш, язычка и анимированного акцента. Pressed-цвет, текст и статическое подтверждение остаются. Prompt updated статично сохраняется те же 1600 ms. Включение reduce во время движения немедленно завершает всё подготовленным результатом и возвращает декор в покой.

| Событие | Поведение |
| --- | --- |
| Документ hidden / существенный width resize / ориентация | Немедленный commit подготовленного результата, остановить все вторичные эффекты, responsive layout пересчитать |
| Только высота mobile visual viewport от адресной строки | Не перезапускать и не завершать вращение, зависящее от ширины |
| Нет WAAPI / ошибка запуска движения | Мгновенный подготовленный результат, статический декор |
| Пустой допустимый набор / ошибка buildPrompt | Ошибка до успешной анимации; сохранить только прежний ещё допустимый результат либо пустое состояние; не восстанавливать недопустимый prompt |
| Пропущенный finish | Watchdog **3200 ms** от визуального старта последовательности: идемпотентный commit без новой выборки |
| Unmount / dev cleanup | Отмена animations/listeners/watchdog/эффектов; не commit и не setState после удаления |

Основной набор WAAPI: общий delay 100 ms, длительности 1380/1860/2340 ms. Ожидать завершение основных лент; не задерживать доступный результат ради вторичного эффекта. Декор обязан закончиться не позднее последнего барабана, оставшиеся callbacks отменяются. Снять filling-effects после статического финального render без отката. cancel может отклонить finished Promise; обработать. Commit идемпотентен по spinId при гонке finish/resize/visibility/watchdog.

В idle никаких активных циклических анимаций и постоянного will-change у всех деталей. Использовать transform/opacity и ограниченные локальные цветовые акценты. Не анимировать layout/тяжёлые blur/shadows на каждом кадре; не вводить новую animation-библиотеку.

## 11. Микропереходы вне SPIN

Hover кнопок — 120 ms, только цвет. Focus-visible появляется немедленно и не перемещается вместе с лицевой частью. Copy pressed — изменение заливки; pending/success/error — немедленные тексты в резерве. How to use — opacity 100 ms, без scale/выезда; доступность и фокус не зависят от transitionend. В reduced mode эти переходы статичны. Repeat-иконка SPIN не вращается отдельно: движение концентрируется на клавише и машинке.

## 12. Будущая приёмка v2

- На 1440/1024/768/640/390/320 видно заметное нажатие; focus и box не прыгают.
- 16/23/30 позиций проходят за заданные интервалы. При остановке Topic в 1480 ms Format/Angle всё ещё быстрые до 1620/2100; при остановке Format в 1960 Angle остаётся быстрым до 2100.
- Ни один запрещённый для текущих настроек label не используется ради декоративного разнообразия. Малый пул честно повторяется, без выдуманных записей.
- Круглые клавиши/колёса живут только во время SPIN, финал возвращает машинку в покой; mobile без выступающих и перекрывающих деталей.
- Новые реальные короткие labels Angle и длинные fixtures, short→long, long→short, шесть строк, font fallback и zoom: текст полностью виден после фиксации, геометрия на commit не схлопывается.
- Одна подготовленная допустимая комбинация, повтор результата разрешён; промежуточные подписи/остановки не выбирают Angle и не меняют вероятности семейств.
- Проверить будущие 15 уровней × 3 длины, совместимость, веса/профили и пустые наборы по каталогам; v2 не подменяет эту проверку красивым движением.
- Быстрые повторные клики, Copy pending, focus/keyboard, screen reader, resize, hidden, reduce до/во время, отсутствие WAAPI, ошибка выбора и unmount.
- Смена настроек, сохранение/сброс результата, Prompt updated и защита по revision; helper words/fields/items и полная строка Copy.
- Performance trace после реализации: отсутствие React render/layout measurement на кадр, fps измерить; сайт полезен при отключённой анимации.

На этапе 2026-10-09 проверялась только документация. При реализации прототипа 2026-10-10 проверены TypeScript и 12 сценариев координации с имитацией времени/DOM/WAAPI. Реальный browser playback v2 не проверен из-за ошибки доступа Browser. Старые browser/runtime-отчёты сохраняются; источники приложения, PNG, продуктовые каталоги и deployment не изменены.
