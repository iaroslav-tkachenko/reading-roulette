# Шаг 11 — адаптация и проверка в браузере

Дата завершения: 2026-10-12. Изменения выполнены локально поверх How to use и полных каталогов. Рабочий dev: [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Проверенная собранная версия: [http://127.0.0.1:5174/reading-roulette/](http://127.0.0.1:5174/reading-roulette/).

Последующие правки: [уплотнение первого экрана](mobile-height/README.md) и [исправление высоты, EN/RU-кнопок, шрифтов и счётчика идей](ui-polish/README.md). Последний отчёт содержит актуальные размеры и проверки после локализации. Ниже сохранён отчёт исходной адаптации.

## Изменения

- До 900 CSS px включительно используется компактная компоновка: язык на отдельной строке, уровень и длина рядом, три барабана друг под другом, крупная SPIN. Сохраняются общие настройки, выбранная комбинация, подготовленные ленты и контроллер цикла. В DOM находится один набор рабочих контролов. Декоративные колёса, клавиши и предметы комнаты остаются в настольной сцене. Компактный вариант подготовлен для пользовательского визуального просмотра.
- Основной шрифт барабанов уменьшен с 29/26/23 до 24/22/20 SVG px. Те же полные подписи используются в покое и движении. Измерение настоящих glyph widths подтвердило попадание всех 100 подписей в окна, с запасом по ширине и без ellipsis.
- Промпт имеет размер не меньше 16 CSS px и интерлиньяж 1.6. Лист расширяется на телефоне, текст переносится, страница прокручивается целиком. Статусы стали контрастнее. Компактные настройки имеют высоту 48 px, SPIN 56 px, Copy не меньше 48 px, справка 44 px.
- Подложка бумаги теперь имеет прямые боковые границы после входа из слота. Рваный край находится в обычном потоке, имеет ту же ширину и новый crop исходного PNG; стык мягко перекрывается на 8 px. Под стаканом добавлены мягкая и контактная тени. Исходные 14 PNG и шрифт сохранены побайтово.
- У настроек усилен видимый фокус; промпт доступен по Tab. Ctrl+A при фокусе в промпте выделяет только его содержимое для ручного копирования. При смене компоновки сохраняется логический фокус на настройке или SPIN. Кнопка справки на узком экране размещается вверху страницы и не закрывает текст листа.
- Resize теперь завершает подготовленный цикл при изменении высоты, а также ширины окна. Результат и промпт фиксируются вместе, а настройки и Copy становятся доступны. Существующие защиты от повторного запуска, скрытия вкладки, ошибок анимации, reduced motion, watchdog и устаревшего ответа clipboard сохранены.

## Проверки

**151 проверка DOM и поведения в настоящем headless Chromium 153.0.8010.12** выполнена на окончательной production-сборке. [Скрипт](browser-checks.mjs), [отчёт](browser-verification.json), [измерения подписей](label-widths.json).

Проверены 13 конфигураций: 320×568, 390×844, 768×1024, 900×700, 901×700, 1024×768, 1366×900, 1536×864, 1920×1080, 2560×1080, 844×390 и мобильная touch-эмуляция 390/320. Контролы помещаются по ширине, промпт не имеет горизонтального overflow, ID уникальны. Проверены клавиатурный фокус, быстрые повторные клики, удержание Enter, согласованная посадка всех трёх барабанов, сохранение старого промпта до финала, блокировка Copy во время SPIN, ручное выделение, справка, resize только по высоте, переходы desktop ↔ compact, ориентация, сохранение фокуса, reduced motion до/во время цикла, ошибка Animation API, настоящий watchdog с приостановленными Animation и восстановление после недопустимой настройки. Ошибок страницы и консоли нет.

**46 нативных проверок в отдельном видимом Chromium** выполнены после явного разрешения пользователя. [Скрипт](native-checks.mjs), [отчёт](native-verification.json).

- Настоящий browser zoom 80/100/125/150/200% через `chrome.tabs.setZoom`, подтверждённый `getZoom`, CSS viewport и DPR; адаптация и SPIN при каждом масштабе.
- Настоящее переключение вкладки во время движения: браузер выдаёт `visibilitychange` и `document.hidden`; цикл завершается подготовленным результатом, после возврата доступны новый SPIN и Copy. Значение `document.hidden` не подменялось, синтетический visibility event не отправлялся.
- Четыре нажатия Copy перенесли полный актуальный промпт в **системный буфер Windows**, подтверждено отдельным `Get-Clipboard`: текущий English, обновлённый Russian, Long/C2 после SPIN, повтор после восстановления разрешения. В сравнении нормализованы только CRLF.
- Настоящий Ctrl+V вставил весь текст в поле другой вкладки. Нативный отказ разрешения Clipboard API показал ручной fallback; Ctrl+A/Ctrl+C из промпта скопировали только его содержимое в Windows. После восстановления разрешения Copy снова сработала. Ошибок страницы и консоли нет.

Встроенный Browser при подключении завершился EPERM. Нативные проверки использовали отдельный новый тестовый профиль; пользовательские профили и окна не управлялись. Обычный запуск Playwright принудительно эмулирует фокус/видимость и потому не доказывает скрытие вкладки. [Тестовый запуск](native-browser.mjs) подключается с `noDefaults: true`; отключено только определение перекрытия окна Windows, нативная видимость вкладок сохранена. Профили тестов находятся в игнорируемом `node_modules/.cache/reading-browser`. Тестовое окно закрывается после выполнения; расширение зума относится только к этому профилю и не входит в приложение.

**61 сохранённая регрессионная проверка**: 495 настроек, 44 формата, 1 936 переходов, 14 784 промпта через тестовый writer; 11 press, 10 drum, 7 key, 6 wheel, 5 pointer и 9 clipboard сценариев. [Скрипт](../implementation-step9-v10/verify.mjs), [отчёт](mechanical-verification.json). Сравнение принятой сцены учитывает только явно изменённые тени стакана, crop/стык листа и адаптацию CSS. Исторические отчёты предыдущих этапов сохранены. Эти SSR/fake-clock проверки отделены от двух настоящих браузерных серий.

TypeScript, production build с `/reading-roulette/`, `git diff --check` и доступность 21 HTTP-ресурса прошли. PNG и шрифт совпадают с эталоном по хешам. Изменения каталога и правил генерации в этот этап не входили. Состояние затронутых файлов перед работой сохранено в [before](before/).

Снимки реального приложения просмотрены визуально: [настольная сцена](desktop-top.png), [мобильная страница 390](mobile-390.png), [верх страницы 320](mobile-320-top.png), [нижний край листа](paper-bottom.png), [нативный зум 200%](native-zoom-200.png).

Проверки выполнены на Windows Chromium. Физический телефон, Safari/Firefox, чтение screen reader и опубликованный HTTPS clipboard этим этапом не проверены. Touch-сценарии являются эмуляцией. Визуальное принятие новой компактной компоновки остаётся за пользователем. Оптимизация графики и публикация относятся к шагу 12; commit, push и deploy в этом этапе не выполнялись.

## Повторный запуск

Используются уже установленные Playwright Core и Chromium на D:, зависимости приложения не изменены. Можно указать другой установленный `playwright`/`playwright-core` через переменную; без неё скрипты импортируют `playwright`.

```powershell
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build --base=/reading-roulette/
```

В отдельных терминалах запустить dev и production-preview:

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort
```

```powershell
node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 5174 --strictPort --base=/reading-roulette/
```

Затем:

```powershell
$env:READING_PLAYWRIGHT_MODULE='D:\Dev\Projects\Language Tracker\node_modules\.pnpm\playwright-core@1.63.0\node_modules\playwright-core\index.mjs'
$env:READING_TEST_URL='http://127.0.0.1:5174/reading-roulette/'
node docs/design/implementation-step11-v10/browser-checks.mjs
```

Следующая команда открывает отдельное тестовое окно и записывает тестовый промпт в системный буфер:

```powershell
$env:READING_TEST_URL='http://127.0.0.1:5173/'
node docs/design/implementation-step11-v10/native-checks.mjs
node docs/design/implementation-step9-v10/verify.mjs
git -c core.safecrlf=false diff --check
```
